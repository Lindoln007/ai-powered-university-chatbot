The problem

University information is hard to find quickly

Information about programmes, admission requirements, fees, registration and student services is spread across prospectuses, notice boards, websites and different offices. Prospective and current students often cannot find a simple answer, and staff answer the same questions again and again.

Ordinary keyword search does not help much, because students rarely use the same words as the official documents. "Which courses can I study here?" and "What programmes does the university offer?" mean the same thing but share almost no words.

The solution

One place to ask, in your own words

The chatbot keeps the university's answers in one central knowledge base. A pre-trained language model turns every question into numbers that represent its meaning, so a question can be matched to the right answer even when it is worded differently.

The chatbot only returns answers that already exist in the knowledge base. It never makes up facts, and it labels every answer that is demonstration information.

Objectives

What the project set out to do

These objectives come from the project specification and README.

  1. A central knowledge baseStore university questions and answers in a database that staff can update without changing code.
  2. Understand meaning, not just wordsMatch questions by meaning using a pre-trained Sentence Transformer model.
  3. Never invent answersReturn only stored, labelled information, or say clearly that no answer was found.
  4. Support guests and registered usersKeep conversation history and collect feedback on answers.
  5. Help staff improve itShow usage, performance and unanswered questions so gaps can be filled.
  6. Open, documented interfacesExpose everything through a documented REST API, with a separate web interface on top.

Intended users

Who the chatbot is for

  • Prospective students

    School leavers and parents asking about programmes, entry requirements, fees and how to apply, often on a phone.

  • Current students

    Students checking registration, examinations, the academic calendar, the library, accommodation and support services.

  • University staff

    Administrators who update the knowledge base and use the analytics to see which questions are still unanswered.

Main functionality

What the chatbot can do

All screenshots below were captured from the running application on 11 November 2026.

Answers questions, with their source

Each answer shows its topic, how closely it matched, and the knowledge-base record it came from. A gold Demo information badge marks answers that are hypothetical demonstration data.

Related questions are suggested underneath. When a question is ambiguous, such as "What about the fees?", the chatbot asks which topic was meant instead of guessing.

Says honestly when it does not know

Questions outside the knowledge base receive a clear fallback message instead of a made-up answer. These questions are recorded so staff can review them and add missing information.

Works on phones

The interface adapts to small screens, which matters because many students use mid-range Android phones. Guests can chat without an account; signing in keeps conversations across devices.

More of the system

About the data

About the data. This is an academic prototype. All 57 knowledge-base answers are clearly labelled hypothetical demonstration information written for testing. They have not been verified with DMI St. John the Baptist University and contain no real fees, dates or contact details.

The system also has an official mode that uses only verified information, ready for when real data is supplied.
