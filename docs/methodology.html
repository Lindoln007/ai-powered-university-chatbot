How the chatbot works

The chatbot is retrieval-based: it finds the stored question that means the same as yours and returns that question's human-written answer. A small pre-trained language model handles the "means the same" part. The facts always come from the university knowledge base.

1 · Architecture

The main parts and how they connect

A browser-based interface talks to a Django backend through a REST API. The backend stores everything in PostgreSQL and uses a local language model for understanding questions.

3 · University knowledge base

Where the answers come from

The knowledge base is a set of frequently asked questions stored in PostgreSQL. Each FAQ has one main question, several alternative wordings of the same question, a written answer, a topic, keywords, a source description, and a verification status.

The initial dataset (data/university_faqs.json) has 57 FAQs with 201 alternative wordings across 12 topics, plus 3 longer articles. It is imported by a command that validates every record and can be re-run without creating duplicates.

Every record is labelled hypothetical demonstration information, because verified university data was not available. The backend enforces this: in official mode only verified records can ever be returned.

4 · Question processing

What happens when a student asks a question

Followed step by step for a real question from the tests: "What grades do I need to qualify?"

  1. Check and tidy the text

    Empty, too long (over 500 characters) or meaningless input is rejected. Extra spaces and odd punctuation are cleaned. No words are removed.

    Text is valid, so it continues.

  2. Turn it into numbers

    The language model converts the question into a list of 384 numbers (an embedding) that represents its meaning.

    384-number meaning vector created in a few milliseconds.

  3. Detect the topic (intent)

    The vector is compared with 65 example phrases for 11 intents, such as admissions or fees. Below 0.40 similarity it is "unknown".

    Intent: admissions enquiry

  4. Compare with every stored question

    It is compared with all 258 stored questions (57 main + 201 alternative wordings) using cosine similarity. Each FAQ keeps its best score.

    Best match: ADM-002 "What are the admission requirements?", score 0.86

  5. Decide: answer, ask, or admit it doesn't know

    Below 0.50: fallback. Above 0.75: answer. In between, if two topics are within 0.03, ask the student to clarify.

    0.86 is above 0.75, so answer directly.

  6. Build the reply and save it

    The stored answer is returned with its source, a demonstration label and related questions. The message and analytics are saved.

    Answer ADM-002 shown with "Demo information" badge.

5 · Semantic search

Matching by meaning, not by keywords

An embedding is a list of numbers that describes what a sentence means. Sentences with similar meanings get similar lists, even if they share no words.

Cosine similarity measures how closely two embeddings point in the same direction, on a scale where 1 means the same meaning and values near 0 mean unrelated. The chatbot answers only when the best score reaches the 0.50 threshold, which was chosen by testing (see page 3).

Embeddings for all stored questions are calculated once and saved in PostgreSQL. They are only recalculated when a question's text changes, so answering a new question needs just one quick calculation.

  • "Which courses can I study?" → PROG-0010.85
  • "How much will I pay per semester?" → FEE-0010.72
  • "Am I allowed to pay my fees bit by bit?" → FEE-0020.60
  • "Who won the football world cup in 2018?" → best match0.27
  • Real scores from the manual test run on 11 November 2026. Scores of 0.50 and above are answered; the football question falls below and gets the fallback reply.

6 · Response generation

Four kinds of reply, all grounded in the knowledge base

The chatbot does not write new text with a generative AI model. Every factual reply is a stored answer, so it cannot invent information.

Reply typeWhen it is usedWhat the student sees
AnswerBest match is clear and at least 0.50The stored answer, its source, a match-strength indicator, a demo label if unverified, and related questions
ClarificationTwo different FAQs score almost the same"Did you mean…?" with the options as buttons
FallbackBest match is below 0.50"I couldn't find verified information…", plus a link to browse topics. The question is logged for staff.
Small talkGreetings, thanks, goodbyeA short friendly reply explaining what the chatbot can help with

Follow-up questions

Short follow-ups such as "How much does it cost?" are understood using the previous topic. The new question's meaning is blended with a smaller share (35%) of the previous one, so "it" is resolved to the right topic. The result must still pass the same threshold, so context never adds new facts.

Safety and data protection

Passwords are hashed, signed-in users use tokens, and guests get a secret session token that is stored only as a hash. Users can only see their own conversations. Requests are rate-limited, and errors never reveal internal details.

7 · Development process

How it was built

  1. Backend and databaseDjango apps, PostgreSQL models, migrations, REST API with authentication and API documentation.
  2. Dataset and importThe 57-FAQ demonstration dataset with alternative wordings, imported and embedded by a repeatable command.
  3. NLP pipelinePreprocessing, intent detection, semantic search, decision rules, follow-up handling and response generation.
  4. Testing and tuningAutomated tests, and a held-out evaluation set used to choose the 0.50 threshold.
  5. Web interfaceA responsive React interface, later rebuilt with a stronger visual design after feedback.
  6. Performance workSwitched the model runtime from PyTorch to ONNX Runtime with identical results, cutting start-up from about 15 seconds to about 3.
