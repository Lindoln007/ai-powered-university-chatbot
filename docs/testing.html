1 · Automated tests Completed

112 automated tests, all passing

The tests run against a temporary PostgreSQL database and use the real language model, not a simulation, so the semantic search results are genuine. They were last run on 11 November 2026: Ran 112 tests … OK.

The most important tests check that differently worded questions get the same answer, and that unrelated questions do not get a confident wrong answer.

2 · Accuracy evaluation Completed

Does it find the right answer for questions it has never seen?

A separate set of 55 new wordings of questions in the knowledge base, plus 20 off-topic questions (weather, football, recipes and so on), was written and kept out of the dataset. The command python manage.py evaluate_retrieval measures the results at different similarity thresholds.

correct FAQ ranked first (no threshold)
51 / 55
correct FAQ in the top three
54 / 55

Choosing the threshold. A threshold that is too low answers off-topic questions; one that is too high refuses good ones. At 0.50 the chatbot answered 50 of the 55 new wordings correctly and refused all 20 off-topic questions, the best overall result (93.3%). At 0.45, one off-topic question ("What time is it in New York?") was wrongly answered with office hours.

4 · Interface checks Completed

Screens, phones and accessibility

The web interface was tested in a browser during development (10 and 11 November 2026), using desktop and emulated phone screen sizes.

  • All pages tested end to end: chat, quick search, browse topics, sign-in and the staff dashboard.
  • No sideways scrolling at a 375 px phone width.
  • 23 text and background colour pairs measured in both light and dark themes: every pair reached at least 4.6 : 1 contrast (WCAG AA requires 4.5 : 1).
  • Keyboard use, visible focus, a skip link and screen-reader announcements for new answers.
  • Touch targets of at least 44 px on touch screens; animations switched off when the device asks for reduced motion.
  • Bugs found and fixed during these checks included the page being wider than a phone screen and overlapping artwork on the sign-in page.

5 · Performance Completed

Speed on an ordinary laptop

Measured on 8 November 2026 on the development laptop (Intel Core i5 11th Gen, 12 GB RAM, no graphics card). Early testing showed the first answer after start-up could take minutes, so the model runtime was changed from PyTorch to ONNX Runtime. Accuracy was re-checked afterwards and was identical.

7 · Limitations

Known limitations

  • The data is hypothetical. None of the 57 answers is verified university information.
  • Near-neighbour mistakes. 5 of the 55 unseen questions were not answered correctly, mostly because a closely related FAQ was chosen instead.
  • English only. The model does not reliably understand Chichewa.
  • Simple context. Follow-ups use only the previous topic; it is not a full conversation manager.
  • One answer at a time. It cannot combine information from several FAQs into one reply.
  • Small, self-written test set. The 75 evaluation questions were written by the developer.
  • Development server. It has not been deployed to a production server.

8 · Recommendations

Next steps

  1. Load verified informationReplace demonstration answers with information confirmed by university offices, then switch to official mode.
  2. Learn from real questionsUse the logged unanswered questions to add FAQs and alternative wordings, then re-run the evaluation.
  3. Pilot with studentsRun user acceptance testing with a small group of prospective and current students on their own phones.
  4. Add Chichewa supportEvaluate a multilingual model such as paraphrase-multilingual-MiniLM-L12-v2.
  5. Deploy properlyUse a production web server over HTTPS, and shared caching if more than one server process is used.
